API Signupanytime www.signupanytime.com/plugins/links/admin/LinksAJAX.aspx
Base: https://www.signupanytime.com/plugins/links/admin/LinksAJAX.aspx?op={OP}&…
Em Playwright, navegar primeiro para o iframe antes de chamar directamente:
…/front/linksviews.aspx?v=results&fmt=nohead&ax=1129&t={t}
GET
?op=GetMeta&t={tcode}
Metadados completos: flights, age_groups, flight_courses (par+yards reais por buraco!), flight_rounds, courses, teeMarkers
→ { tournament{name, start_date, end_date, rounds}, flights, age_groups, flight_courses{pars[], lengths[], course}, flight_rounds, courses }
GET
?op=GetTournamentPlayers&t={tcode}&f={fid}
Lista de memberIDs de todos os inscritos num flight. Fase 1 do member-history.
→ { PlayerNodeId: number[] }
GET
?op=GetPlayerTeeTimes&f={fid}&r={round}&p={page}&t=0
Principal fonte de scores buraco-a-buraco. Paginado, 20 jogadores/página.
→ { flight_players: { [pid]: { first, last, country, place, status, rounds: { [rn]: { strokes[18], num_strokes, num_holes, start_hole, start_time, group_number } } } } }
GET
?op=GetMemberTournamentResults&m={memberID}
Histórico completo de um membro — todos os torneios USKids da carreira. Pode ter dezenas de torneios.
→ { [tcode]: { t_name, t_start_date, t_end_date, t_rounds, t_pars[], t_yards[], p_age_group, p_status, p_place, p_strokes, p_points, p_rounds: { [rn]: { strokes[18], num_strokes, num_holes, course_name, start_hole, start_time } } } }
EVENT
page.on('response') filtrar URL contém op=GetMeta&t={t}
Em Playwright: intercetado via listener ao navegar para o iframe. Mais fiável do que chamar directamente.

Estruturas JSON — o que está dentro de cada ficheiro referência rápida
pull-torneiosNNN.json · drive-data.json · aquapor-data.json FPG Pull ▼
Formato "fpg-pull" — usado por FPGPage, DrivePage, KIDSdataLoader. Dois formatos: antigo (single-round flat) e novo (multi-round com roundScores[]).
{ tournaments: TournamentEntry[] } TournamentEntry = { name, ccode, tcode, date: "YYYY-MM-DD", campo, clube?, circuit?, series?, players: PlayerEntry[] } PlayerEntry = { scoreId, pos, name, club, grossTotal: number|string|null, toPar: number|string|null, fedCode?, ← nfed do jogador hcpExact?, ← hcp exacto no dia hcpPlay?, ← hcp de jogo (arredondado) course?, ← nome do campo courseRating?, ← CR da tee jogada slope?, teeName?, nholes?, ← 9 ou 18 parTotal?, ← par do percurso // Formato ANTIGO (single-round, flat): scores?: number[18], par?: number[18], si?: number[18], meters?: number[18], // Formato NOVO (multi-round): roundScores?: [{ round: number, ← 1-based gross: number, scores: number[18], ← resultado por buraco pars: number[18], ← par por buraco si: number[18], ← stroke index meters: number[18], ← distância em metros courseRating?, slope?, teeName?, teeColorId? }] }
⚠ Armadilha: grossTotal pode ser string (ex: "WD", "DNS") ou number. Sempre testar antes de usar como número.
uskids-results.json USKids results ▼
Gerado por fetch-uskids-results.js. Contém scorecards buraco-a-buraco + par/yards reais. par[] vem da ronda ou via USKIDS_PAR no loader.
{ resultados: Torneio[] } Torneio = { t: number, ← tcode signupanytime name: string, escaloes: [{ nome: string, ← "Boys 11" age_group: number, rondas: [{ ronda: number, ← 1-based buracos?: number, ← 9 ou 18 par?: number[], ← par por buraco (pode faltar) yards?: number[], ← jardas por buraco leaderboard: [{ nome: string, pais: string, ← "PT", "US", etc. score: number, ← gross desta ronda buracos: number, to_par?: number|null, strokes?: number[18], ← resultado por buraco rondas?: Record<"1", { strokes?: number[] }> }] }] }] }
⚠ Armadilhas: strokes[] pode estar ausente (jogadores sem scorecard completo). par[] nem sempre existe na ronda — usar USKIDS_PAR["{tcode}-{age_group}"] como fallback no KIDSdataLoader.
uskids_torneios_completos(N).json USKids completo ▼
Gerado pelo script browser. Formato v2 — tem todos os flights, par/yards reais, scorecards completos. Contador TORNEIOS_COMPLETOS_COUNT = 19.

Armadilhas, bugs encontrados e lições aprendidas 2 meses de descobertas
Separação de pipelines — NÃO misturar USKids com FPG/BJGT na tab Resultados Crítico ▼
⚠ Este bug voltou várias vezes. Torneios não-USKids (Doral, WJGC, Greatgolf, QDL, EOWAGR) devem alimentar apenas a tab Rivais via buildAutoRivals(). A tab Resultados carrega exclusivamente de uskids-results.json e uskids_torneios_completos(1-19).json. Qualquer fetch destes ficheiros noutro loader contamina a sidebar de resultados.
Pipeline OKResults tab → uskids-results.json + uskids_torneios_completos → USKIDSPage Pipeline OKRivals tab → buildAutoRivals() → KIDSdataLoader → todos os JSON internacionais Pipeline ❌Nunca chamar processWjgc/processDoral dentro do loader de resultados
Manuel tem 3 variantes de nome nos JSON — usar filter() não find() Crítico ▼
Manuel aparece como "Manuel Medeiros", "Manuel Francisco Medeiros" e "Manuel Goulartt Medeiros" em diferentes fontes. autoRivals.find() só apanha a primeira variante. Usar sempre autoRivals.filter() e fazer merge de todas as entradas.
Padrão correctoconst manuelAll = autoRivals.filter(d => d.isM); depois merge dos torneios de todas as entradas getScorecards()Também aggregates — compara first+last word tokens, não nome completo exacto
Referências estáticas a dados fora de componentes React ficam stale Crítico ▼
Qualquer const manuel = D_BASE.find(x => x.isM) declarado fora de um componente ou hook referencia dados pré-merge. Depois do merge assíncrono, o objecto nos rivals state tem mais torneios, mas a referência estática nunca actualiza.
FixDentro de RivalDetail: const manuelMerged = rivals.find(d => d.isM) (lookup dentro do componente, usa o state)
scrape-drive-aquapor-v7.js: R1=R2 em torneios de 2 rondas (v6 bug) ▼
v6: usava classif.aspx/ScoreCard com classifround=2 — a API ignora o parâmetro e devolve sempre R1, resultando em R1=R2 no JSON.
v7: usa classifAgregate.aspx/ScoreCard (com classifround="") que devolve um array de Records (1 por ronda). Ficheiro correct a partir de v7.
ScorecardLeaderboard: par vazio causa somas zero (bug subtle) ▼
siTotal = si.slice(0, nh).reduce() onde nh = par.length. Se par[] chegar vazio, nh=0, slice devolve [], soma = 0, {0 || ""} renderiza em branco. Fix: usar nhRef = nh > 0 ? nh : (is9 ? 9 : 18) como fallback.
Fixconst nhRef = par.length || (is9 ? 9 : 18) — nunca depender de par.length para derivar nBuracos
Duplicados no normCountry e TW causam warnings Vite e lentidão ▼
10 entradas duplicadas em normCountry no USKIDSPage (barbados, bahamas, vietnam, israel, venezuela, etc.) + TW:"Taiwan" duplicado no KIDSdataLoader causavam warnings de "Duplicate key" e recompilação lenta no Vite. Removidos.
KIDSdataLoader: filtro 18H bloqueava torneios de 9 buracos (El Prat) ▼
O filtro scores.length === 18 em processWjgc e processUskids bloqueava todos os torneios de 9H. El Prat 2023 (9H) não aparecia. Fix: usar expectedHoles = par.length (dinâmico) em vez de hardcoded 18.
Nota adicionalEl Prat também precisou de entrada manual em USKIDS_PAR["15573-2151"] com par [4,3,4,5,4,3,4,4,5] (9H)
Irmãos com mesmo apelido: falsos positivos no matching de rivais ▼
Dois irmãos com o mesmo apelido eram considerados o mesmo jogador pelo scoreMatch(). Fix: penalizar matches onde os primeiros 3 caracteres do primeiro nome diferem (first-name prefix penalty).
displayName(): nomes em ALL CAPS precisam de normalização ▼
Alguns JSON (BJGT, WJGC antigos) guardam nomes em ALL CAPS ("JOHN SMITH"). A função displayName() detecta quando >45% dos caracteres são maiúsculos e converte para Title Case. Usar sempre displayName(nome) antes de renderizar nomes de jogadores.
lengths[] nos completos são jardas, não metros ▼
O campo meta.flight_courses[].lengths[] nos uskids_torneios_completos está em JARDAS. Converter com ×0.9144 para metros. A app faz a conversão automaticamente em USKIDSPage.tsx (função yardsToMetros()).
applyResultOverrides(): injectar scores do Manuel quando ele é WD nos dados ▼
Manuel foi marcado como desistente (WD) nos dados do Marco Simone 2026 Boys 11, mas jogou. A função applyResultOverrides() em USKIDSPage.tsx injeta manualmente os seus scores R1/R2 no array resultados após o load.
processUskidsCompleto: strokes[] sempre tem 18 posições ▼
Nos torneios completos, strokes[] tem sempre 18 posições mesmo para torneios de 9H. Para F9: posições 0-8 têm valores, 9-17 = 0. Para B9: posições 0-8 = 0, 9-17 têm valores. Filtrar os zeros antes de somar/exibir.
